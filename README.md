# xui-monitor-bot

[![CI](https://github.com/Hijackery/xui-monitor-bot/actions/workflows/ci.yml/badge.svg)](https://github.com/Hijackery/xui-monitor-bot/actions/workflows/ci.yml)

**Русский** · [English](README.en.md)

Telegram-бот для сервера с панелью 3X-UI: следит за железом, systemd-сервисами
и панелью, присылает алерты, показывает подписки и трафик. Опасные действия
(рестарт сервиса, xray, обновление системы, перезагрузка) выполняются только
с подтверждением кнопкой и только администратором.

## Что нужно

- Linux; менеджер служб определяется автоматически: **systemd**
  (Debian/Ubuntu, RHEL/CentOS/Rocky/Alma, Fedora, openSUSE, Arch/Manjaro) или
  **без systemd** — OpenRC (Alpine, Gentoo) и SysVinit. Пакетный менеджер тоже
  определяется сам (`apt`/`dnf`/`yum`/`zypper`/`pacman`). Выбрать вручную:
  `--init systemd|openrc|sysv`.
- Python 3.10+ — установщик подберёт подходящий интерпретатор сам.
- Панель 3X-UI и её API-токен.
- Бот в Telegram (токен от [@BotFather](https://t.me/BotFather)) и ваш numeric ID
  (узнать: [@userinfobot](https://t.me/userinfobot)).

## Установка

```bash
bash <(curl -Ls https://raw.githubusercontent.com/Hijackery/xui-monitor-bot/main/install.sh)
```

или через пайп:

```bash
curl -fsSL https://raw.githubusercontent.com/Hijackery/xui-monitor-bot/main/install.sh | sudo bash
```

Скрипт сам скачает код, спросит токены, поставит зависимости, создаст системного
пользователя `xui-monitor`, включит автозапуск и в конце проверит, что всё
работает. **Мастер задаёт вопросы сразу — четвёртым шагом, до установки
зависимостей,** поэтому отвечать нужно в начале. Вопросы читаются с терминала,
поэтому диалог идёт и при установке через пайп.

GitHub может отдавать ветку из кэша пару минут после обновления репозитория —
если увидели старую версию, просто повторите команду чуть позже. Архив с кодом
скачивается с меткой времени и всегда актуален.

API-токен панели нужен со scope `node-sync` — иначе бот не увидит inbound'ы и
подписки:

```bash
sudo x-ui setting -getApiToken true -tokenName monitor-bot -tokenScope node-sync
```

Без вопросов (значения из окружения):

```bash
sudo env \
  TELEGRAM_BOT_TOKEN='123456789:AA...' \
  TELEGRAM_ADMIN_IDS='11111111' \
  PANEL_URL='https://panel.example.com:2053' \
  PANEL_API_TOKEN='...' \
  bash install.sh --yes
```

Полезные опции: `--repo owner/name`, `--ref ветка`, `--prefix DIR`,
`--user NAME`, `--no-start`, `--force-config`, `--print-source` (показать, откуда
будет взята версия), `--sha256 HASH`, `--menu`. Полный список — `--help`.


## Меню настроек (`xui-menu`)

После установки в системе появляется консольная панель — быстрее, чем править
`.env` руками:

```bash
sudo xui-menu          # интерактивное меню
sudo xui-menu show     # текущие настройки (секреты замаскированы)
sudo xui-menu keys     # какие ключи разрешено менять
xui-menu check PANEL_TIMEOUT 20   # проверка значения без изменений (без root)
sudo xui-menu set PANEL_TIMEOUT 20
sudo xui-menu restart  # применить
sudo xui-menu logs 100
```

Структура интерактивного меню:

```text
1) Состояние службы и ошибки        7) Пороги алертов (CPU)
2) Показать настройки               8) Изменить любой ключ по имени
3) Сменить токен бота               9) Перезапустить бота
4) Сменить ID администраторов      10) Журнал бота (50 строк)
5) Панель: адрес                   11) Обновить бота
6) Панель: API-токен               12) Удалить бота (спросит yes)
```

Что делает каждый пункт:

| Пункт | Действие |
|---|---|
| 1 | `systemctl status` + последние предупреждения из журнала бота |
| 2 | показать настройки; токены замаскированы (`123456 ···a1b2`, короткие — `*** (N символов)`) |
| 3–6 | пошаговая смена токена бота, ID админов, адреса панели, API-токена панели |
| 7 | порог `CPU_WARN` (остальные пороги — через пункт 8) |
| 8 | правка любого ключа из белого списка по имени (`xui-menu keys`) |
| 9 | перезапуск бота с проверкой, что служба активна |
| 10 | журнал бота (50 строк) |
| 11 | обновление: берёт локальную копию установщика из `/opt/xui-monitor-bot/install.sh` (она обновляется при каждом запуске), либо скачивает с GitHub, и запускает с тем же `PREFIX` |
| 12 | удаление; меню отдельно попросит ввести `yes` |

Что важно знать:

- менять можно только ключи из белого списка (`xui-menu keys`); значения
  проверяются до записи (`check`) — например, `LOG_LEVEL` принимает лишь
  `DEBUG/INFO/WARNING/ERROR`, а `PANEL_URL` обязан начинаться с `http`;
- `.env` перезаписывается атомарно с правами `640 root:<сервисный пользователь>`,
  как при установке; правки применяются после перезапуска (меню предложит);
- секреты никогда не печатаются целиком, и `.env` не нужно никому пересылать —
  в нём лежат оба токена;
- пути можно переопределить: `sudo PREFIX=/opt/бот ENV_FILE=/opt/бот/.env xui-menu`.

### Если в системе нет systemd

Установщик поставит `/etc/init.d/xui-monitor-bot` (`start`/`stop`/`status`/
`restart`) и зарегистрирует автозапуск через `rc-update` (OpenRC) либо
`update-rc.d`/`chkconfig` (SysVinit). Управление, `.env`, sudoers-обёртка и
`xui-menu` работают так же; журнал берётся из файла `bot.log`, если `journalctl`
недоступен. Отличия: нет systemd-изоляции юнита, а `/services` показывает, что
состояние служб недоступно (бот напишет об этом в «Требует внимания»).

## Обновление и удаление

```bash
# обновить (конфиг и состояние сохранятся)
bash <(curl -Ls .../install.sh)

# удалить бота (служба, sudoers, обёртка, код)
sudo bash install.sh --uninstall

# то же, но вместе с состоянием и системным пользователем
sudo bash install.sh --purge

# интерактивное меню
sudo bash install.sh --menu
```

## Команды

| Команда | Что показывает |
|---|---|
| `/status` | общая сводка: сервер, сервисы, панель, трафик |
| `/services` | состояние systemd-юнитов, рестарт, журнал |
| `/panel` | доступность панели и xray, версии, обновления |
| `/subs` | подписки: сроки, трафик, отключённые |
| `/history` | почасовые средние CPU/RAM/диска за сутки |
| `/logs` | журнал выбранного сервиса |
| `/audit` | журнал действий бота |
| `/maint` | обслуживание: apt (full-upgrade и phased upgrade), релиз-обновление, произвольная команда |
| `/help` | список команд |

Кнопки под сообщениями дублируют команды: у каждого экрана есть «🏠 В меню», так
что в тупике оказаться нельзя. Гостям бота кнопки не показываются.

Команды и кнопки работают **только в личном чате** администратора: в группе бот
отвечает отказом, чтобы адреса, подписки и трафик не утекли в общий чат.

`/status` начинается с вердикта одной строкой (`всё в норме` / `сервисы не
работают: …`), замечания идут сразу за ним, а детали спрятаны за
`📋 Подробнее` — ночью достаточно одного экрана. Метрики выровнены
моноширинным блоком, время подписано «время сервера».

Кнопки собирают данные с промежуточным «⏳», после действия остаются
контекстные кнопки (например, журнал перезапущенного сервиса). Под алертом
сразу есть `♻️ Рестарт <сервис>`, `📜 Журнал` и `😴 Знаю, до утра` — заглушить
конкретную проблему на 8 часов (мьют хранится в SQLite и переживает
перезапуск). Журнал сервиса умеет `🔎 Только ошибки` и `📜 Ещё 200 строк`,
а `/audit` — фильтры «отказы / действия». Подтверждения объясняют последствия
(«панель и VPN отключатся на 1–2 минуты»). Перезагрузка сервера — в `/maint`
→ `🔻 Перезагрузить сервер`, за подтверждением.

## Настройки

Все параметры — в `/opt/xui-monitor-bot/.env`, пример с комментариями —
[`.env.example`](.env.example).

| Ключ | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather |
| `TELEGRAM_ADMIN_IDS` | ID администраторов через запятую |
| `ALERT_CHAT_ID` | чат для алертов (пусто — админам в личку) |
| `TELEGRAM_API_URL` | свой Bot API или прокси (по умолчанию официальный) |
| `PANEL_URL` | адрес панели, например `https://panel.example.com:2053` |
| `PANEL_BASE_PATH` | `webBasePath` панели, если задан |
| `PANEL_API_TOKEN` | токен панели (scope `node-sync`) |
| `PANEL_VERIFY_TLS` | проверять TLS-сертификат панели (по умолчанию `true`) |
| `PANEL_CA_BUNDLE` | свой CA-файл (PEM) для панели; перекрывает `PANEL_VERIFY_TLS` |
| `PANEL_TIMEOUT` | таймаут запросов к панели, сек |
| `SERVICES` | юниты под наблюдением, через запятую (`x-ui,fail2ban`) |
| `DISK_PATH` | что проверять по месту |
| `CPU_WARN` | порог предупреждения по CPU, % |
| `CPU_CRIT` | порог критического CPU, % |
| `MEM_WARN` | порог предупреждения по RAM, % |
| `MEM_CRIT` | порог критического RAM, % |
| `DISK_WARN` | порог предупреждения по диску, % |
| `DISK_CRIT` | порог критического диска, % |
| `ALERT_HYSTERESIS` | на сколько % метрика должна отойти назад, чтобы сбросить алерт |
| `ALERT_COOLDOWN` | как часто повторять активный алерт, сек |
| `EXPIRING_SOON_DAYS` | за сколько дней подписка считается истекающей |
| `CHECK_INTERVAL` | период фоновой проверки, сек (минимум 15) |
| `ACTION_COOLDOWN` | пауза между одинаковыми действиями, сек |
| `CONFIRM_TTL` | сколько живёт кнопка подтверждения, сек |
| `COMMAND_TIMEOUT` | таймаут разрешённых команд, сек |
| `COMMAND_ALLOWLIST` | список команд для диагностики (должен совпадать с `install/xui-ctl`) |
| `STATE_PATH` | база SQLite |
| `LOG_PATH` | файл лога |
| `LOG_LEVEL` | `DEBUG` / `INFO` / `WARNING` / `ERROR` |
| `SUDO_WRAPPER` | путь к `xui-ctl` |

Переменные окружения процесса имеют приоритет над файлом `.env`.

## Безопасность

- Бот работает непривилегированным пользователем `xui-monitor`; код и venv
  принадлежат root, `.env` доступен сервису только на чтение.
- Все привилегированные операции идут через `/usr/local/bin/xui-ctl` и узкий
  sudoers-список; произвольного shell нет. `apt` выполняется отдельным
  transient-юнитом systemd, потому что сервис живёт с `ProtectSystem=strict`.
- Опасные действия требуют подтверждения, токен привязан к запросившему
  администратору, всё пишется в `audit_log`.
- Клиент панели не следует редиректам (иначе токен мог уйти на чужой хост),
  значения из панели экранируются перед отправкой, токен бота не попадает в
  логи даже на `DEBUG`.
- Повторы защищены: одно подтверждение срабатывает один раз, одинаковые действия
  ограничены `ACTION_COOLDOWN` (включая рестарт xray), а сообщения, которые
  Telegram отклонил из-за flood control, отправляются повторно.
- Команды принимаются только в личном чате; попытки доступа посторонних
  пишутся в журнал (`denied`), чтение журнала сервисов ограничено по частоте.
- Нестандартный `TELEGRAM_API_URL` отмечается предупреждением в логе, а
  установщик умеет проверять контрольную сумму архива (`--sha256`).
- Для самоподписанного сертификата панели есть `PANEL_CA_BUNDLE`: вместо
  отключения проверки TLS можно подсунуть свой CA и держать пиннинг.

## Если что-то не работает

```bash
systemctl status xui-monitor-bot
journalctl -u xui-monitor-bot -n 50 --no-pager
```

- «Токен отклонён» — проверьте `TELEGRAM_BOT_TOKEN` и `PANEL_API_TOKEN`
  (удобнее через `sudo xui-menu` → «Показать настройки» / «Сменить токен бота»).
- `inbounds/list недоступен` — у токена панели нет scope `node-sync`.
- Логи сервиса не видны — проверьте, что в sudoers есть правило `journal`.
