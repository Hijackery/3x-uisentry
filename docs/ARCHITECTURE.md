# Архитектура

StackSentry — долгоживущий процесс на сервере с Telegram-интерфейсом, локальным
read-only Mini App и отдельным терминалом. Код разделён так, чтобы сбой панели
не ронял отчёт по серверу, а привилегированные операции проходили только через
узкий контролируемый вход.

## Компоненты

| Модуль | Ответственность |
|---|---|
| `stacksentry/app.py` | Telegram-хендлеры, меню, подтверждения, 2FA, фоновые задачи |
| `stacksentry/monitor.py` | Сбор снимка состояния; изоляция источников и `unavailable` |
| `collectors/system.py` | CPU/RAM/swap/диск/сеть через `psutil` и `/proc` |
| `collectors/services.py` | Состояние служб (systemd/OpenRC/SysV) |
| `collectors/panels.py` | Адаптеры панелей: 3X-UI, Marzban, Marzneshin, PasarGuard, Remnawave, S-UI, Hiddify, Outline |
| `collectors/subscriptions.py` | Нормализация inbound'ов/пользователей в подписки и проблемы |
| `inventory.py` | Определение ОС, пакетного менеджера, панелей, VPN и служб |
| `alerts.py` | Правила, гистерезис, антидребезг, доставка алертов |
| `actions.py` | Очередь действий и вызов `stacksentry-ctl` |
| `storage.py` | SQLite: история метрик, аудит, состояние алертов |
| `webapp.py` | Read-only Mini App: initData, HttpOnly-cookie, CSP |
| `updates.py` | Проверка обновлений по commit `main`; сравнение с `.stacksentry-install` |
| `terminal/` | Web/root-терминал с обязательным TOTP, локальным SSH-ключом, тикетами и отдельным пользователем |
| `install/stacksentry-ctl` | Единственная точка привилегированных операций |

## Поток данных

```text
таймер/кнопка
      │
      ▼
 Monitor.snapshot()
      │  system, services, panel health, subscriptions
      ▼
 MonitorSnapshot ──► Telegram-экраны
      │
      ├────────────► AlertEngine ──► алерт + кнопки действий
      └────────────► Storage (история, аудит)
```

Каждый источник собирается изолированно: исключение превращается в запись
`unavailable`, а не в ложное «восстановлено». Прошлые состояния не объявляются
здоровыми, пока источник снова не ответит.

## Панели

`PanelFacade` — единая точка для `Monitor` и `ActionManager`.

- 3X-UI использует существующий `PanelClient` (Bearer, `/panel/api`).
- Остальные адаптеры наследуют общий HTTP-клиент с таймаутом, проверкой TLS/CA и
  запретом редиректов (чтобы токен не ушёл на сторонний хост).
- Ошибки нормализуются: `PanelForbidden` — авторизация/права, `PanelError` —
  сеть, HTTP, не-JSON, ошибка панели.
- 3X-UI присылает `success=false` с HTTP 200; S-UI делает так же. Это
  обрабатывается отдельно, чтобы «успешный» HTTP не считался успехом.

## Безопасность

- Сервис работает от `stacksentry`; код и venv принадлежат `root`, `.env` —
  `640 root:stacksentry`.
- Привилегированные операции — только `stacksentry-ctl` с фиксированным списком
  подкоманд; аргументы валидируются, произвольного shell нет.
- Опасные действия требуют подтверждения и (опционально) свежего TOTP.
- Команды принимаются только в личном чате администратора; отказы аудируются.
- Секреты вырезаются из логов и сообщений; Telegram ID маскируются.
- HTTP-клиенты панелей не следуют редиректам и поддерживают пиннинг CA.
- Docker API намеренно не используется.
- Self-update запускается отдельным юнитом, требует подтверждения и свежего TOTP;
  `stacksentry-ctl update_bot` проверяет root-владельца установщика и фиксирует
  `--ref main`, без пользовательских аргументов.

## Расширение

Чтобы добавить панель:

1. Добавьте тип в `Settings` (`PANEL_TYPE`), `inventory.API_PANEL_TYPES`,
   установщик и меню.
2. Реализуйте клиент в `collectors/panels.py`: `health()`, `subscriptions()`,
   `restart_xray()` (или явную ошибку, если API не умеет).
3. Добавьте ветку в `PanelFacade` и `SubscriptionCollector`.
4. Добавьте тесты маппинга, ошибок авторизации и рестарта.
5. Обновите `docs/COMPATIBILITY.md`, README и CHANGELOG.

## Надёжность

- Фоновые обновления идут через systemd-юниты или `setsid`-воркер, а не внутри
  сервиса с `ProtectSystem=strict`.
- Очередь действий ограничена кулдауном; результат и код возврата пишутся в
  аудит.
- SQLite используется с WAL и короткими транзакциями; история ограничена
  настройками.
- CI прогоняет тесты на Python 3.10 и 3.13, а также проверяет shell-скрипты,
  sudoers и форматирование.
